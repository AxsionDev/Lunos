Lunos is an EU-sovereign, self-hostable AI coding agent, forked from
[opencode](https://github.com/sst/opencode). This is the first of what will be a regular set of
notes about building it in the open — including the parts that are not working.

This sprint was foundation work. Almost none of it is a feature, and that is the honest framing:
we spent the week making the fork _ours_ rather than adding to it.

## What shipped

- **The name is frozen: Lunos.** After three renames in three days (AXCODE → Ratio → Lunos), the
  name is settled and the repo, npm package, and release assets all agree on it. The CLI publishes
  as `lunos-ai` and installs a `lunos` binary.
- **The README now leads with what this project is for** — sovereignty and deployability under EU
  law — rather than with a feature comparison against upstream.
- **Inherited CI is triaged.** We audited all 26 workflows carried over from upstream, dropped the
  8 that only made sense for the parent project, and moved the correctness gates onto runners a
  fork can actually use.
- **A one-page landing site with email capture is up.**
- **An upstream sync policy is written and adopted** — see below, it is the decision worth reading.
- **The "why we forked opencode" FAQ is drafted**, held back until launch.

## What we decided, and why

**We sync with upstream by merging, never rebasing.** This started as a style preference and ended
as a measurement. Rebasing our fork onto upstream produced **109 conflicts**; merging the same
upstream state produced **zero**. The reason is structural: our changes are concentrated in
branding, CI configuration, and fork-owned documentation, which touch many files shallowly.
Rebasing replays every one of those against every upstream commit; merging resolves them once.

We wrote the policy down rather than leaving it as tribal knowledge, because the rebase instinct is
strong and the cost only shows up after you have committed to it.

**Fork-owned files go in fork-owned paths.** Anything we add that upstream will never have —
policies, drafts, these notes — lives under a path upstream does not use. Every file we add at the
root of a shared directory is a merge conflict we have chosen to pay for repeatedly. This note is
in `.claude/docs/notes/` for exactly that reason, and the per-release changelog stays generated by
the existing pipeline rather than hand-maintained alongside it.

**We are not announcing yet.** The project is still close to an unmodified fork. A loud launch now
would spend the one good first impression on something that does not yet differ from its parent in
any way a user would notice. The work is public; the announcement waits for a real differentiator.

## What is still broken or unproven

- **Clean-machine install is not verified end-to-end** (XCOD-20). Release asset naming was fixed
  this sprint so the installer and the pipeline finally agree, but the full path from
  `curl | sh` to a working binary on a fresh machine has not been proven. Until it is, treat the
  install instructions as unverified.
- **Nothing is code-signed** (XCOD-49). macOS, Windows, and Tauri signing credentials are all
  missing. Downloads will trip OS gatekeepers.
- **Phase 0 is not closed** (XCOD-15).
- **Trademark clearance for "Lunos" is outstanding.** The name is frozen for engineering purposes;
  that is not the same as cleared. There are at least three active commercial users of the word in
  adjacent spaces.
- **The README still lacks a terminal GIF and the parity table.** Both are known gaps, not
  oversights.
- **No EU-specific functionality exists yet.** The sovereignty positioning describes where this is
  going, not where it is. That work is Phase 1.
