# Backend Patterns

> Auto-generated by `/generate-startup`. Do not edit manually.
> Framework: Effect (`effect/unstable/httpapi`) — no ASP.NET/Express/Hono equivalent; this is a CLI/TUI product, not a hosted API.

## Handler Pattern

Handlers are defined with `HttpApiBuilder.group`, one `Effect.fn` generator per operation, binding services to named variables before use (never nested `yield*`):

```ts
// packages/server/src/handlers/credential.ts
export const CredentialHandler = HttpApiBuilder.group(Api, "server.credential", (handlers) =>
  handlers
    .handle(
      "credential.update",
      Effect.fn(function* (ctx) {
        yield* (yield* Integration.Service).connection.update(ctx.params.credentialID, { label: ctx.payload.label })
        return HttpApiSchema.NoContent.make()
      }),
    )
    .handle(
      "credential.remove",
      Effect.fn(function* (ctx) {
        yield* (yield* Integration.Service).connection.remove(ctx.params.credentialID)
        return HttpApiSchema.NoContent.make()
      }),
    ),
)
```

## Dependency Direction (enforced)

Schema → Core/Protocol → Server. Client runtime code may depend on Schema and Protocol but never Core or Server; `sdk-next` composes Client, Core, and Server. Do not invert this when adding new imports.

## Codegen

After changing the public Protocol or Server `HttpApi`, run `bun run generate` from `packages/client`. Never hand-edit `src/generated` or `src/generated-effect`.

## Build & Test

- Typecheck: `cd packages/server && bun typecheck` (never `tsc` directly)
- Test: `cd packages/opencode && bun test` — root `test` script is a deliberate guard and will exit 1
- Full-repo typecheck: `bun run typecheck` (root → `bun turbo typecheck`)
