# Supply chain

## How Lunos is built and released

- **Source:** public, MIT-licensed, at [github.com/AxsionDev/Lunos](https://github.com/AxsionDev/Lunos).
  It is a fork of [opencode](https://github.com/anomalyco/opencode).
- **Builds:** every release is built and published by the repository's own GitHub Actions workflow
  (`.github/workflows/publish.yml`), not from a developer's machine.
- **Changes:** go through pull requests into `dev`, with typecheck, unit, end-to-end and Nix
  evaluation checks in CI. Branch protection is **not** enabled on `dev` yet, and there is no
  static application security testing (SAST) in CI yet.

## Verifying what you install

| What                                                       | Available                                                           | How to verify                                                                                                   |
| ---------------------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| npm packages (`lunos-ai` and platform packages)            | **Now**                                                             | `npm audit signatures`: npm provenance (SLSA attestations) links each package to the workflow run that built it |
| Release archives (`SHA256SUMS`, Sigstore-signed)           | **From v1.18.40**                                                   | `cosign verify-blob` against the repository's workflow identity, then `sha256sum --check`                       |
| SBOM (CycloneDX), Sigstore-signed                          | SBOM on every release; signature and licence data **from v1.18.40** | `cosign verify-blob` on the SBOM's bundle                                                                       |
| OS code signing (Apple Developer ID, Windows Authenticode) | **Not available**                                                   | Gatekeeper and SmartScreen will warn. Install through npm, or allow the binary manually                         |

Copy-paste commands: [deployment guide, "Verify your download"](../deployment/self-hosted.md#verify-your-download).

## Software bill of materials

A CycloneDX SBOM (`lunos-sbom-<version>.cdx.json`) is generated by
[syft](https://github.com/anchore/syft) for every release and attached to it. From v1.18.40
it also carries each component's licence (v1.18.40: 2,158 of 2,166 components), and the
release job fails if fewer than 95% have one.

## Extensions from the marketplace

The built-in `lunos-community` catalogue lists plugins, MCP servers, skill sources and hooks.

- **Criteria and review log:** [marketplace review](../marketplace-review.md). Every listed entry
  must carry an OSI-approved licence. Two entries were removed on that basis.
- **Status today:** every entry is `community`: listed, **not reviewed** by a person against the
  full criteria. The catalogue records each entry's licence, pinned version and (for npm packages)
  integrity hash.
- **From v1.18.40:** installs pin to the listed version and refuse a package whose registry
  integrity doesn't match the catalogue; installing an unreviewed entry needs `--allow-unreviewed`,
  which organisation policy can forbid; marketplaces can be restricted to an allow-list.
- **Not covered:** MCP servers launched with `npx`, `uvx` or `docker` fetch their code when they
  start. Their commands are pinned to a version or image digest, but no install-time integrity check
  applies to them.
